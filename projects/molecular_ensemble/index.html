Multimodal Pipeline for Target-Specific Drug Discovery: From SELFIES to 3D Equivariance#

Introduction: The Funnel Philosophy#

Drug discovery is, at its core, a search space problem of incomprehensible scale. The theoritical chemical universe of synthetically viable, drug-like molecules is estimated to be around $10^{60}$. Even if we restrict ourselves to known, synthesizable libraries like Enamine REAL, we are still looking at billions of compounds.

Traditional High-Throughput Screening (HTS) in a wet lab tops out at a few million compounds and costs millions of dollars. Standard computational Virtual Screening (VS) using classical physics engines like AutoDock Vina can process more, but it is still fundamentally a “needle in a haystack” approach; you are testing random molecules hoping one happens to fit your target receptor.

Instead of searching a static library, the modern AI approach is De Novo Generation: teaching a model the grammar of chemistry and asking it to generate novel molecules specifically tailored for a target (in this case, the Mpro protease of SARS-CoV-2 from the COVID Moonshot dataset).

However, you cannot simply plug a generative language model directly into a 3D physics engine. Physics-informed, Equivariant Graph Neural Networks (EGNNs) and diffusion-based docking models (Diffdock-Pocket) are computationally heavy. Running a 3D point-cloud evaluation on millions of raw, generated sequences is hardware-impossible, even on A100 clusters.

The Pipeline Architecture Overview The system is orchestrated to pass molecules through the following stages, ensuring that only the most viable, non-toxic, and highly specific candidates ever reach the final 3D physics engine:

  • Phase 1: De Novo Generation (The Source). We abandon SMILES strings which frequently result in mathematically invalid outputs during autoregressive sampling, in favor of SELFIES. A Causal Transformer (SELFIES-GPT) is pre-trained on the MOSES dataset to learn general valency, then fine-tuned on the COVID Moonshot dataset to generate novel Mpro-targeted geometries.
  • Gate 1: The Multimodal ADMET Oracle (1D + 2D). Before calculating spatial binding affinity, a molecule must be biologically viable. This gates uses a MultimodalFusionScorer that cross-attends a 1D sequence (via a SMILES Transformer) with 2D topological graph features (via a Directed-MPNN). It acts as a high-speed filter to score Toxicity, Solubility, Mutagenicity, and hERG liability. Molecules that fail here are instantly discarded.
  • Gate 2: The Dimensionality Upgrade (2D -> 3D). The surviving “elite” molecules are upgraded from flat topological graphs into 3D conformers in a vacuum, preparing them for spatial interaction.
  • Gate 3a: Physics-Informed Posing (DiffDock Pocket). To evaluate binding, the ligand must be accurately positioned inside the protein. We utilize DiffDock specifically targeted at the Mpro active site to generate physically viable, clash-free docking poses.
  • Gate 3b: SE(3)-Equivariant Scoring (EGNN). The final, most computationally expensive step. An Equivariant Graph Neural Network (Gate3_EGNNScorrer) processes the 3D point cloud of the protein-ligand complex. Because it is strictly SE(3) equivariant, it understands the 3D spatial geometry (push/pull atomic forces) regardless of rotational orientation, predicting a highly accurate binding affinity ($pK_{d}$).

Throughout this project, data integrity was a strict architectural constraint. There is no “faking” data downstream; the final UI and evaluation metrics strictly utilize the precomputed elites that legitimately survived Gate 1, preserving their original, unmodified generated geometries through the 3D scoring phase.

In the following sections, we will open up the source code for each of these models, exploring the mathematical necessity of the architectures, the loss functions, and the hardware-specific optimizations required to train them.

2. Phase 1: De Novo Generation with SELFIES-GPT#

To discover a novel Mpro inhibitor, the pipeline must hallucinate entirely new chemistry. We treat molecular geenration as an autoregressive language modeling task. However, applying Natural Language Processsing to chemistry requires solving a fundamental representational bottleneck.

2.1 The Representation Bottleneck: SELFIES vs. SMILES#

The industry standard, SMILES, is highly fragile. It relies on strict topological syntax for branching () and ring closures 1...1. In an autoregressive generation scenario, if the model predicts C1CCCCC but fails to predict the closing 1 due to stochastic sampling, the entire string collapses into a mathematically invalid graph.

To guarantee 100% syntactical validity, the pipeline’s phase1_tokenizer.py translates all SMILES into SELFIES (SELF-referencing Embedded Strings). SELFIES operates on a Chomsky Type-0 grammar designed for machine learning. Every permutation of a SELFIES sequence maps to a physically valid molecular graph, forcing the loss landscape to reflect actual chemical properties rather than syntactical errors.

2.2 Model Architecture: The Causal Transformer#

The core engine is SELFIESGeneratorGPT, a decoder-only Transformer built natively in PyTorch. The model projects tokenized discrete inputs into a continuous embedding space $d_{model} = 256$, across 6 layers and 8 attention heads.

Because Transformers are permutation-invariant, spatial order is injected using absolute sinusodial Positional Encoding before the sequence enters the attention blocks:

$$PE_{(pos,2i)} = sin \left( \frac{pos}{(1000^{2i/d_{model}})} \right)$$ $$PE_{(pos,2i+1)} = cos \left( \frac{pos}{(1000^{2i/d_{model}})} \right)$$

The Causal Masking Logic To prevent the model from “cheating” by looking at future tokens, we apply a strict causal mask M. This is an upper-triangular matrix where the upper elements are set to $- \infty$ (or in PyTorch’s boolean masking, True means “ignore”).

When calculating scaled Dot-Product Attention, this mask is added to the unnormalized attention logits before the softmax operation:

$$Attention(Q, K, V) = softmax \left( \frac{QK^{T}}{\sqrt{d_{k}}} + M \right) V$$ In selfies_gpt.py, instead of relying on external decoder modules, I implemented this by passing a strictly generated upper-triangular matrix directly into PyTorch’s TransformerEncoderLyar:

def forward(self, src):
    device = src.device
    seq_len = src.size(1)
    pad_mask = (src == self.pad_idx)
    
    # Generate the strict Causal Mask matrix
    causal_mask = torch.triu(torch.ones(seq_len, seq_len, dtype=torch.bool, device=device), diagonal=1)

    src_emb = self.embedding(src) * math.sqrt(self.d_model)
    src_emb = self.pos_encoder(src_emb.transpose(0, 1)).transpose(0, 1)
    
    output = self.transformer_stack(
        src_emb, 
        mask=causal_mask,             
        src_key_padding_mask=pad_mask, 
        is_causal=True 
    )
    return self.fc_out(output)

This forces the prediction for token $x_{t}$ to be strictly conditioned on the joint probability distribution of preceding tokens: $P(x_{t} | x_{1}, x_{2}, x_{3},…, x_{t-1})$.

2.3 Training Strategy and Hardware Optimization#

We utilize a two-stage transfer learning pipeline:

  1. General Domain (MOSES): The model is pre-trained from scratch on ~2M molecules to learn baseline chemical valency.
  2. Target Domain (COVID Moonshot): Pre-trained weights are loaded via strict=True, and the model is fine-tuned on the COVID Moonshot dataset to shift the distribution toward Mpro-active chemotypes.

The Fine-Tuning Loop (finetune_selfies_gpt.py)

The objective function is Cross-Entropy Loss applied across the flattened sequence, explicitly ignoring the padding index to prevent the model from optimizing for empty space:

$$\mathcal{L} = -\sum_{c=1}^{V} y_{o,c} \log(p_{o,c})$$ (where $V$ is the vocab size, and $p_{o,c}$ is the predicted probability of the correct token).

To push maximum throughput on A100 GPU, the fine-tuning script abandons standard FP32 math.

  1. TF32 and BFloat16: TensorFloat-32 is enabled globally, and the forward pass is scoped inside an autocast('cuda', dtype=torch.bfloat16) context. bfloat16 retains the 8-bit exponent of FP32 (preventing underflow) while dropping the mantissa to 7 bits, allowing A100 Tensor Cores to process the math natively.
  2. Kernel Fusion: In PyTorch 2.0+, torch.compile is invoked. This traces the computation graph and fuses pointwise operations (like the GELU activations and Dropouts inside the Transformer layers) into optimized Triton kernels, vastly reducing memory bandwidth overhead.
# Enable Tensor Cores for matrix math
torch.backends.cuda.matmul.allow_tf32 = True

# Kernel Fusion for A100
if int(torch.__version__.split('.')[0]) >= 2:
    model = torch.compile(model)

optimizer = optim.AdamW(model.parameters(), lr=5e-5, weight_decay=1e-4)
criterion = nn.CrossEntropyLoss(ignore_index=pad_idx)

# Inside the training loop:
with autocast('cuda', dtype=torch.bfloat16):
    logits = model(x)
    logits_flat = logits.view(-1, tokenizer.vocab_size)
    y_flat = y.view(-1)
    loss = criterion(logits_flat, y_flat)

Because torch.compile modifies the internal module reference, saving the weigths directly would corrupt the checkpoint for later inference. The script cleanly unwraps the compiled model via unwrapped_model = model._orig_mod before saving the state dictionary.

2.4 Inference and Generation#

During inference, we seed the model with a start token. The model outputs a probability distribution over the vocabulary space of $V$ tokens for position $t$. We sample the next token (often scaling the logits by a temperature parameter $T$ to control diversity: $q_{i} = \frac{exp(z_{i}/T)}{\sum_{j} exp(z_{i} / T)}$, append it to the sequence, and feed the new sequence back into the model until an End-of-Sequence token is generated.

This engine successfully generates novel, Mpro-biased SELFIES strings. However, a generated sequence does not guarantee biological safety. For that, these molecules must pass through Gate 1.

3. Gate 1: The Multimodal ADMET Oracle (1D + 2D)#

A generative model optimizing strictly for protein binding will often hallucinate highly reactive, toxic, or insoluble molecules. In drug discovery, ADMET (Absorption, Distribution, Metabolism, excretion, and Toxicity) is just as critical as binding affinity.

however, chemical properties are dictated by different dimensional representations. Some properties (like logP or solubility) are easily captured by 1D sequences motifs, while others (like steric hindrance or specific toxicity alerts) require an understanding of 2D graph topology.

To create a high-speed, highly accurate ADMET filter, Gate 1 employs a Multimodal Fusion Architecture. It independently processes the molecule as a 1D sequence and a 2D graph, dynamically fusing the representations before passing them to a multi-task prediction head.

3.1 The 1D Sequence Encoder: SMILES Transformer#

While Phase 1 uses SELFIES for autoregressive generation, Gate 1 utilizes SMILES. Because Gate 1 is a predictive filter (not a generator), the fragility of SMILES is no longer an issue, and SMILES strings often provide a more compact representation of functional groups for Bidirectional Transformers.

The 1D encoder (transformer.py) is a 4-layer, 8-head BERT-style Transformer Encoder ($d_{model} = 128$).

Pre-training via masked language Modeling (MLM)

Before predicting ADMET properties, the Transformer must understand chemistry. I built a custom DataCollatorForMLM that dynamically pads sequences and applies the classic 80/10/10 masking rule to 15% of the tokens:

  • 80% of the time, the token is replaced with [MASK].
  • 10% of the time, it is replaced with a random token (forcing the model to rely on contextual correction).
  • 10% of the time, it is left unchanged (teaching the model that the input might already be correct).

Engineering Detail: The A100 Fast-Path Crash

During heavily batched mixed-precision training on A100 GPUs, PyTorch’s native Nestedtensor “Fast Path” for Transformers frequently triggered memory access violations when dealing with dynamically padded SMILES sequences. To ensure stability during the 20-epoch pre-training loop, I explicitly disabled it inside the encoder block:

self.transformer_encoder = nn.TransformerEncoder(encoder_layer, num_layers=num_layers)

# FIXING THE A100 CRASH
# Disables the "Fast Path" optimization to prevent memory violations on dynamic padding
self.transformer_encoder.enable_nested_tensor = False

During the forward pass, we throw away the rest of the sequence and extract only the [CLS] token at index 0, yielding a continuous vector representation of the 1D sequence.

3.2 The 2D Topological Encoder: Directed-MPNN#

Standard Graph Convolutional Networks (GCNs) process molecules by passing messages between atoms (nodes). This leads to a severe problem known as “tottering.” A message will travel from Atom A to Atom B at step $t$, and then bounce right back from Atom B to Atom A at step $t + 1$. This creates an artificial echo chamber of redundant noise, drowning out the actual topological structure of the rings and chains.

To solve this, the pipeline uses a Directed Message Passing Neural Network (D-MPNN)(D_MPNN.py). Instead of updating node states, it updates directed edge states (bonds).

let $h_{vw}^{(t)}$ be the hidden state of the directed bond from atom $v$ to atom $w$. To update this bond, we sum the messages from all incoming bonds to $v$, subtracting the exact reverse bond $w \rightarrow v$ :

$$m_{vw}^{(t+1)} = \sum_{k \in N(v) \setminus {w}} h_{kv}^{(t)}$$ In the PyTorch Geometric implementation, this requires maintaining an index to quickly grab the reverse of every edge:

# Create an index to quickly grab the reverse of every edge
num_edges = edge_index.size(1)
reverse_indices = torch.arange(num_edges, device=x.device)
# Swap evens and odds: [1, 0, 3, 2, 5, 4 ...]
reverse_indices[0::2] = torch.arange(1, num_edges, 2, device=x.device)
reverse_indices[1::2] = torch.arange(0, num_edges, 2, device=x.device)

# Directed Message Passing
messages_to_edges = node_messages[sender_nodes]
reverse_edge_hidden = edge_hidden[reverse_indices]

# The Chemprop D-MPNN core logic: subtract the reverse edge
directed_messages = messages_to_edges - reverse_edge_hidden
edge_update = F.relu(self.edge_norms[i](self.W_h[i](directed_messages)))

# Add the update to the INITIAL state h^0 to prevent oversmoothing
edge_hidden = F.relu(initial_edge_hidden + edge_update)

After updating the edges across $N$ layers, the edge states are aggregated back to the receiver atoms via a highly efficient scatter reduction (which acts like a SQL GROUP BY operation for tensors).

Finally, a Global Attention Pool (GATE network) calculates a dynamic importance score (0 to 1) for each atom, outputting a single 128-dimensional vector representing the 2D topology of the molecule.

3.3 The Cross-Attention Fusion Layer#

We now have two representations: a 1D sequence vector and a 2D graph vector. Simple concatenation ($[v_{1D}, v_{2D}]$) is suboptimal because it doesn’t allow the two modalities to interact contextually.

Instead, fusion_layer.py implements a Cross-Attention Mechanism. The GNN topological vector acts as the Query ($Q$), while the full, unspooled Transformer sequence acts as the Keys ($K$) and Values ($V$) :

$$Fused = softmax \left( \frac{Q_{gnn}K^{T}{transformer}}{\sqrt{d{k}}} \right) V_{transformer}$$ This allows the topological structure of the molecule to “look” across the 1D sequence and attend specifically to the structural motifs that match its graph, creating a deeply fused representation before passing it to a shared dense backbone.

3.4 Multi-Task Learning via Dynamic Uncertainty Weighting#

The fused vector is passed to four distinct prediction heads: Hepatoxicity (Classification), Mutagenicity (Classification), Solubility (Regression), and hERG Liability (Classification).

Training a Multi-Task Learning (MTL) network is notoriously difficult because gradients from different tasks often fight each other. Furthermore, some datasets (like hERG classifications) are highly noisy and prone to false positives in the lab. If we apply equal loss weights, the network will destroy its shared backbone trying to fit the hERG noise.

To prevent this, I implemented Homoscedastic Uncertainty Weighting (custom_lossfunction.py). Rather than manually tuning hyperparameter weights for each task, the model initializes four learnable parameters log ($\sigma_{i}^{2}$).

The dynamic loss function is defined as:

$$\mathcal{L}{total} = \sum{i=1}^{4} \left( \frac{1}{2\sigma_i^2}\mathcal{L}i + \frac{\log(\sigma_i^2)}{2} \right)$$ If the hERG dataset is producing chaotic, contradictory gradients, the model will naturally increase $\sigma{hERG}^{2}$ to minimize the overall loss. This effectively down-weights the hERG gradient contribution dynamically, acting as a learned, self-adjusting temperature scale.

In code, this is implemented using $log(variance)$ for numerical stability to avoid division by zero:

class DynamicMultiTaskLoss(nn.Module):
    def __init__(self, num_tasks=4, base_weights=None):
        super(DynamicMultiTaskLoss, self).__init__()
        self.num_tasks = num_tasks
        
        # To permanently weaken noisy datasets
        base_weights = base_weights or [1.0] * num_tasks
        self.register_buffer('base_weights', torch.tensor(base_weights, dtype=torch.float32))

        # Learnable variance parameters initialized to 0 (equal weight of 1.0)
        self.log_vars = nn.Parameter(torch.zeros(num_tasks))
        
        self.bce_loss = nn.BCEWithLogitsLoss()  
        self.mse_loss = nn.MSELoss()            

    def forward(self, masked_preds, masked_targets):
        # Uncertainty weighting: Loss * exp(-log_var) + (log_var / 2)
        precision = torch.exp(-self.log_vars[i])
        dynamic_loss = (loss * precision) + (self.log_vars[i] / 2.0)

        final_task_loss = dynamic_loss * self.base_weights[i]
        total_loss += final_task_loss

By adding a base_weights multiplier, I maintain the ability to manually handicap inherently unreliable assays permanently, while letting the model fine-tune the relative importance of the remaining tasks epoch-by-epoch.

Molecules that survive this rigorous ADMET filtering are deemed “elite.” They are chemically valid, target-biased, non-toxic, and highly soluble. However, they are still just flat sequences and graphs. To determine if they actually bind to the Mpro pocket, we must pull them into the third dimension.

4. Gate 2: Bridging the Dimensional Gap (2D to 3D)#

Up to this point in the pipeline, our generated molecules exist purely in mathematical abstraction, as sequences of tokens or 2D topological graphs. However, biology operates in three dimensions. The binding affinity of an Mpro inhibitor is strictly governed by spatial interactions: hydrogen bonds, Van der Waals forces, and steric clashes inside the protein pocket.

Before we can evaluate how a ligand interacts with a protein, we must first collapse the 2D graph into a physically viable 3D object.

The ETKDG Conformer Generation

Generating a 3D structure from a 2D graph is a non-trivial inverse problem. A single molecule can adopt millions of different 3D shapes (conformers) by rotating around its single bonds.

For this initial transformation, Gate 2 relies on RDKits’s ETKDG (Experimental-Torsion Knowledge Distance Geometry) algorithm. ETKDG improves upon standard distance geometry by incorporating experimental knowledge from the Cambridge Structural Database (CSD).

Instead of randomly embedding the atoms and minimizing them with a generic force field (like MMFF94), ETKDG applies basic physical constraints:

  • Distance Bounds: Ensuring bond lengths and angles match established chemical atoms.
  • Torsional Preferences: Biasing the dihedral angles of the generated conformer to match experimentally observed low-energy states.
# Generate initial 3D Conformer in a vacuum
mol = Chem.MolFromSmiles(smiles)
mol = Chem.AddHs(mol) # Explicit hydrogens are critical for 3D physics
AllChem.EmbedMolecule(mol, AllChem.ETKDG())

The output of Gate 2 is a chemically accurate 3D molecule. However, this conformer is generated in a vacuum. The lowest-energy shape a molecule takes in empty space is rarely the shape it adopts when binding to a protein (the bioactive pose). To find that active pose, we must move to Gate 3a.

5. Gate 3a: Physics-Informed Posing with Diffdock-Pocket#

By the end of Gate 2, we have used ETKDG to generate a valid, low-energy 3D conformer of our generated molecule. However, this conformer was generated in a vacuum. When a ligand enters a protein pocket, it twists, folds, and adapts its shape to maximize favorable interactions (hydrogen bonds, Van der Waals forces) and minimizes steric clashes..

To evaluate if our generated molecule actually binds to the Mpro active site, we must find this bioactive pose.

5.1 The Failure of Classical Search Algorithms#

For decades, the industry standard for this step has been classical docking softwares like AutoDock Vina, Glide, or SMINA. These tools treat docking as a stochastic search problem. They place the ligand in the pocket, randomly mutate its translation, rotation, and dihedral (torsional) angles, and calculate and empirical energy score.

This breaks down at scale for two reasons:

  1. The Combinatorial Explosion: A ligand with $m$ rotatable bonds has an exponential number of possible conformations. Searching this highly non-convex energy landscape using Genetic Algorithms or Monte Carlo sampling almost guarantees getting trapped in a local minimum.
  2. Empirical Scoring: Classical scoring functions heavily approximate quantum mechanics. They often fail to correctly penalize subtle steric clashes, leading to physically impossible overlapping atoms.

To bypass this, the pipeline treats docking not as a search problem, but as a Generative Modeling Problem using Diffusion.

5.2 Generative Diffusion over $SE(3) \times SO(2)^{m}$#

When we think of diffusion models (like Midjourney or Stable Diffusion), we think of adding Gaussian noise to 2D pixel arrays. You cannot do this with molecules. If you add independent Gaussian noise to the X, Y, Z coordinates of every atom, you will tear the bonds apart and destroy the molecule’s chemical identity.

Instead, DiffDock operates on the natural physical degrees of freedom of the ligand. It diffuses over a specific mathematical manifold, a product space defined as:

$$\mathcal{M} = SE(3) \times SO(2)^{m}$$

  • $SE(3)$ (Special Euclidean Group): represents the 6 degrees of freedom for the global position of the ligand relative to the protein (3 for translation, 3 for 3D rotation).
  • $SO(2)^{m}$ (Special Orthogonal Group): Represents the 1D rotational angles (torsions) for the $m$ rotatable single bonds inside the ligand.

The Forward Process (Adding Noise):

During training, the model takes a perfectly bound protein-ligand co-crystal structure from the PDB. It applies a Stochastic Differential Equation (SDE) to gradually randomize the ligand’s translation, rotation, and torsional angles until the ligand’s pose is pure noise (completely detached and randomized).

The Reverse Process (Denoising to the Bioactive Pose):

At inference, we start with our random ETKDG vacuum conformer from Gate 2. The neural network’s job is to predicted the score, the gradient of the log probability density of the data at a given noise level $t$:

$$s_{\theta}(x, t) \approx \nabla_{x} \log p_{t}(x)$$ By plugging this score network into a reverse-time SDE or ODE solver, the model iteratively “denoises” the ligand’s coordinates. It physically pulls the ligand into the pocket and twists its bonds until it perfectly conforms to the protein’s active site.

5.3 The Computational Optimization: DiffDock-Pocket#

Standard DiffDock is designed for Blind Docking. It initializes the ligand far away from the protein and forces the diffusion model to search the entire surface area of the receptor to find the binding pocket.

While scientifically impressive, blind docking is computationally expensive. The integration space for the $SE(3)$ translation diffusion scales cubically $(O(V^{3}))$ with the size of the bounding box. For target-specific generation, this is a massive waste of GPU cycles because we already know where the Mpro active site is (the catalytic dyad of His41 and Cys145).

To optimize this for our high-throughput funnel, the pipeline utilizes DiffDock-Pocket. Instead of sampling the initial translation noise from a wide distribution covering the whole protein, we heavily constrain the initial bounding box.

# Conceptual representation of the Pocket-Constrained Diffusion
# By limiting the translation variance, we skip the "search" phase 
# and dedicate all reverse-diffusion steps to "refinement"
pocket_center = torch.tensor([10.0, -2.0, 23.0])  # Mpro Active Site Coords
translation_variance = 5.0  # Constrained 5 Angstrom radius

# Initialize ligand state close to the pocket
ligand_pos = sample_gaussian(mean=pocket_center, var=translation_variance)

By constraining the $SE(3)$ translation space, we achieve two things:

  1. Massive Speedup: We can drastically reduce the number of inference steps (e.g., from 40 steps to 15 steps) required by the ODE solver, because the model no longer has to drag the ligand across the protein surface.
  2. Higher Precision: 100% of the network’s capacity is spent on high-resolution torsional refinement $(SO(2)^{m})$ and resolving atomic clashes, rather than global pathfinding.

5.4 The Output#

The output of Gate 3a is a single, physics-informed docked_ligand.sdf file. We have successfully taken a hallucinatory text strings (SELFIES), filtered it for biological viability (Gate 1), given it 3D mass (Gate 2), and folded it into the target receptor (Gate 3a).

We now have a true physical complex. The final, definitive step is to accurately calculate the binding affinity $(pK_{d})$ of this complex using a model that fundamentally understands 3D spatial geometry: The EGNN.

6. Gate 3b: $SE(3)$-Equivariant 3D Scoring (EGNN)#

By the end of Gate 3a, the pipeline has generated a chemically valid sequence, filtered it for biological safety, and used diffusion to fold it into a physically viable 3D pose inside the Mpro active site.

The final task is to act as an oracle: evaluating this 3D point cloud to predict the exact binding affinity $(pK_{d})$. This is the most computationally and mathematically demanding step in the entire architecture.

6.1 The Equivariance Imperative#

Predicting molecular properties from 3D coordinates is notoriously difficult. If you need the raw $(X, Y, Z)$ coordinates of a protein-ligand complex into a standard Multi-Layer Perceptron (MLP) or a 3D-Convolutional Neural Network, the model will fail.

The reason is spatial orientation. If a protein is rotated by 90 degrees in space, its underlying biology and binding affinity remain exactly the same, but every single coordinate value changes completely. A standard neural network has to “re-learn” the same molecule form thousands of different angles (a brute-force approach called data augmentation), which is hopefully inefficient for complex point clouds.

To solve this, the pipeline’s scoring engine is an Equivariant Graph Neural Network (EGNN). It guarantees that if the input coordinates are rotated or translated, transformations define by the Special Euclidean group $SE(3)$, the internal vector representations update synchronously. This preserves the fundamental geometric relationships perfectly without requiring any artificial data augmentation.

6.2 Data Engineering: Complex Graph Construction#

To train a model to predict real-world binding affinity, we cannot use generated data; we need wet-lab truth. The EGNN is trained on the PDBbind Refined Set, a highly curated database of experimentally resolved protein-ligand co-crystal structures.

Before the network can process these complexes, the build_complex_graph module translates them into spatial graphs. For every atom in both the protein and the ligand, we extract 10 specific RDKit features:

  1. Atomic Number
  2. Degree (Connectivity)
  3. Gasteiger Partial Charge
  4. Aromaticity
  5. Atomic Mass
  6. Explicit Valence
  7. Hydrophobicity (LogP contribution)
  8. Formal Charge
  9. Van der Waals Radius
  10. A binary flag (is_ligand)

To make message passing computationally tractable, we define a $10.0$ Å pocket_radius around the ligand and discard the rest of the protein. We then compute the pairwise Euclidean distance matrix torch.cdist(prot_pos, lig_pos) and use a $5.0$ Å distance cutoff to create edges between any interacting atoms, establishing the paths for message passing.

6.3 The Architecture#

The core of the model is the Gate3_EGNNScorrer. It takes the atomic features, 3D positions, and edge indices, and processes them through 6 layers of equivariant message passing.

Here is the exact architecture block defining the network:

class Gate3_EGNNScorrer(nn.Module):
    def __init__(self, hidden_dim=256, num_layers=6, num_rbf=32):
        super().__init__()
        # 1. Input Encodings
        self.embedding = nn.Embedding(100, hidden_dim)
        self.feature_lin = nn.Linear(8, hidden_dim)

        # 2. Radial Basis Function (RBF) Initialization
        rbf_range = torch.linspace(0, 5, num_rbf)
        self.register_buffer('rbf_range', rbf_range)
        self.rbf_coeff = -0.5 / (self.rbf_range[1] - self.rbf_range[0]).item()**2

        # 3. The Equivariant Layers
        self.layers = nn.ModuleList([EGNN_Layer(hidden_dim, num_rbf) for _ in range(num_layers)])
        
        # 4. The Predictive Head
        self.mlp_head = nn.Sequential(
            nn.Linear(hidden_dim, 128),
            nn.SiLU(),
            nn.Dropout(0.3),
            nn.Linear(128, 1)  # Outputs a single float: pKd (Binding Affinity)
        )

The Radial Basis Function (RBF) Expansion Notice the RBF initialization. Instead of operating on absolute coordinates, the EGNN operates entirely on relative distances. However, passing distance as a single scalar provides a weak gradient signal.

During the forward pass, the model “smears” the continuous distance into 32 discrete, differentiable Gaussian bins (edge_attr):

diff = pos[edge_index[0]] - pos[edge_index[1]]
dist = torch.sqrt(torch.sum(diff**2, dim=-1, keepdim=True) + 1e-8)
edge_attr = torch.exp(self.rbf_coeff * (dist - self.rbf_range)**2)

This provides a rich spatial embedding for the network to learn smooth physical interactions like Van der Waals forces.

6.4 Inside the EGNN Layer: The Mathematics of Equivariance#

Inside each EGNN_Layer, three distinct Multi-Layer Perceptrons (MLPs) update the graph simultaneously. This is where the actual $SE(3)$ physics simulation occurs.

  1. The Edge Update (edge_mlp): We compute the message $m_{ij}$ between atom $i$ and atom $j$ by concatenating their node features $h$ and the RBF distance embedding: $$m_{ij} = SiLU (W \cdot \left[h_{i},h_{j}, a_{ij} \right] )$$
  2. The Coordinate Update (coord_mlp)-The Equivariant step: the network updates the 3D coordinates by predicting a scalar weight (pos_weight) for every edge. It then multiplies this weight by the relative vector $(x_{i} - x_{j})$. Because we only scale the relative difference vector, this operation applies “push/pull forces” that are strictly $SE(3)$-equivariant.
# Compute Coordinate Updates 
pos_weight = self.coord_mlp(m_ij)
pos_update = coord_diff * torch.clamp(pos_weight, min=-10., max=10.)

pos_aggr = scatter(pos_update.float(), row, dim=0, dim_size=pos.size(0), reduce='sum').to(pos.dtype)
pos_new = pos + (pos_aggr / counts.to(pos.dtype))
  1. The Feature Update (node_mlp)-The Invariant Step: The node features are updated by aggregating the message $m_{ij}$. Because the messages were derived from distances (which do not change when the molecule is rotated), the resulting node features are completely rotationally invariant.

$$h_i^{l+1} = h_i^l + \phi_h \left( h_i^l, \sum_{j \neq i} m_{ij} \right)$$

6.5 The Architectural Trick: Ligand-Centric Readout#

After 6 layers of equivariant message passing, the protein pocket has exerted its “forces” on the ligand, and the ligand’s features reflect its environment.

A standard Graph Neural Network would run a global mean pool over the entire graph to predict the final score. However, doing so would drown the signal of the tiny ligand (e.g., 40 atoms) in the massive noise of the protein pocket (e.g., 1000 atoms).

Instead, the Gate3_EGNNScorrer employs a Ligand-centric Readout. Using the is_ligand boolean mask injected during graph construction, I slice the tensor to pool only the ligand atoms before passing it to the final MLP:

ligand_mask = (x[:, 9] == 1.0)
h_ligand = h[ligand_mask]
batch_ligand = batch[ligand_mask]

# Pool ONLY the ligand's invariant representations
if h_ligand.size(0) > 0:
    pooled = global_mean_pool(h_ligand, batch_ligand)
else:
    pooled = global_mean_pool(h, batch)

return self.mlp_head(pooled)

By forcing the MLP to predict binding affinity solely from the ligand’s final embedded state, the network must learn how to protein alters the ligand, rather than just memorizing the static macroscopic shape of the target pocket.

6.6 Hardware Optimization: Bypassing the I/O Bottleneck#

Parsing complex PDB and SDF files with RDKit at runtime creates CPU bottleneck, starving the GPU and dropping the utilization to near 10%.

To solve this, I implemented an SSD Tensor Cache in train_egnn.py. During the first epoch, the CPU parses the RDKit files and instantly serializes the compiled PyTorch Geometric graphs directly to an NVMe SSD. For all subsequent epochs, the Dataloader bypasses RDKit entirely, streaming raw tensor memory straight to the GPU.

cache_path = os.path.join(self.cache_fir, f"{pdb_id}.pt")

# FAST PATH: If we already built this graph, load it from the SSD instantly 
if os.path.exists(cache_path): 
	return torch.load(cache_path)

Paired with torch.amp.autocast('cuda', dtype=torch.bfloat16) to optimize Tensor Core matrix multiplication without gradient underflow, this custom caching layer ensures the EGNN trains at absolute maximum hardware throughput.

7. The Orchestrator: System Integration#

The models we discussed, SELFIES-GPT, the Multimodal ADMET Oracle, Diffdock-Pocket and the EGNN, are fundamentally different architectures operating on entirely different mathematical representations (1D sequences, 2D graphs, and 3D point clouds). To unify these, I built an Orchestrator(orchestrator.py). The orchestrator manages the handoff between the generative engine and the scoring gates, handling the data transformations (e.g., $SMILES \rightarrow ETKDG conformers \rightarrow DiffDock poses$) required at each step. When executed, the orchestrator:

  1. Triggers the autoregressive generation of Mpro-targeted SELFIES.
  2. Translates the SELFIES to SMILES and batches them through the 1D/2D ADMET Oracle (Gate 1).
  3. Takes the surviving “elite” molecules, generates their 3D ETKDG conformers, and saves them to temporary SDF files (Gate 2).
  4. Programmatically invokes the DIffDock-Pocket diffusion process to fold the ligands into the receptor (Gate 3a).
  5. Compiles the resulting 3D complexes into PyTorch Geometric tensors and runs the final EGNN scoring pass (Gate 3b).

8. Deployment and The UI Trade-off#

Deploying it to the web so that others can interact came with some trade-off. The project is deployed using a decoupled monorepo architecture:

  • backend/: Contains the FastAPI routing, model weights, and the Python ML logic.
  • molecular-ensemble-ui/: The Vercel-deployed frontend dashboard for interactive exploration.

The Compute Bottleneck: Web UX vs. Physics Simulation

While Phase 1 and Gate 1 are highly optimized and can run live inference behind a web endpoint, Gate 3a introduces a severe constraint. Running reverse-diffusion over $SE(3)$ to fold a molecule into a protein pocket requires massive, sustained GPU compute. In a production web environment, forcing a user to wait minutes for a synchronous DiffDock batch to complete is an architectural anti-pattern that leads to browser timeouts and crashes queues.

The Solution: Honest Visualization

To solve this, the UI deployment utilizes a hybrid approach:

  1. Live Generation and Filtering: The UI can trigger SELFIES-GPT and the Gate 1 ADMET oracle dynamically.
  2. Precomputed Elites for 3D Scoring: For the final 3D docking and EGNN scoring phase, the dashboard transitions to visualizing a precomputed orchestrator.py run.

Crucially, the data provenance is strictly maintained. The UI does not “fake” the pipeline by pasting randomly generated names over static scores. The dashboard exclusively displays the true “elite” molecules that legitimately generated via Phase 1, survived Gate 1, and were processed through DiffDock by the orchestrator.

By separating the heavy end-to-end compute script from the web visualization layer, the system maintains 100% scientific integrity while still providing a lightning fast, responsive dashboard for others to explore the physics grounded candidates.
